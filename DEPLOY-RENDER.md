# Putting the backend on Render (with a free MongoDB Atlas database)

About 20 minutes. You need: a GitHub account, a Render account, a MongoDB Atlas account. All free.
This setup is for testing. Riders won't get SMS codes yet: you read them from Render's logs.

---

## Part 1. The database (MongoDB Atlas)

1. Go to **https://www.mongodb.com/cloud/atlas/register** and sign up (Google sign-in is fine).
2. When it offers to create a cluster, choose **M0 (Free)**.
   - Provider: **AWS**
   - Region: **Frankfurt (eu-central-1)**. Render will run in Frankfurt too, so they're close.
   - Name: `caliphate` (anything works)
   - Click **Create Deployment**.
3. It asks you to **create a database user**:
   - Username: `caliphate`
   - Password: click **Autogenerate** and **copy it somewhere safe**. Autogenerated passwords only
     have letters and numbers, which avoids problems later.
   - Click **Create Database User**.
4. **Network access** (left menu → *Security → Network Access*) → **Add IP Address** →
   **Allow access from anywhere** (`0.0.0.0/0`) → **Confirm**.
   Render's free plan doesn't have a fixed address, so this is needed. The password still protects it.
5. **Get the connection string**: left menu → *Database → Clusters* → **Connect** → **Drivers**.
   Copy the string. It looks like:

   ```
   mongodb+srv://caliphate:<db_password>@caliphate.ab12cd.mongodb.net/?retryWrites=true&w=majority&appName=caliphate
   ```

   Change two things:
   - replace `<db_password>` with the password from step 3 (no `< >`);
   - put `caliphate` right after `.mongodb.net/` so the database has a name:

   ```
   mongodb+srv://caliphate:Xy7Kp2Qm9Ld4@caliphate.ab12cd.mongodb.net/caliphate?retryWrites=true&w=majority&appName=caliphate
   ```

   Keep this string: it's your `MONGODB_URI`.

## Part 2. The code on GitHub

Render deploys from a GitHub repository.

1. Unzip **caliphate-backend.zip**. You get a folder with `package.json`, `src`, `public`, `scripts`…
2. On GitHub: **+ → New repository** → name it `caliphate-backend` → **Private** → **Create repository**.
3. On the new repository's page, click **uploading an existing file**.
4. Open the unzipped folder, select **everything inside it** (not the folder itself) and drag it onto
   the GitHub page. `package.json` must end up at the top level of the repository, not inside a folder.
5. Click **Commit changes**.

(If you use Git on your computer instead: `git init`, `git add .`, `git commit -m "Backend"`, then push.)

---

## Part 3. The server (Render)

1. Go to **https://dashboard.render.com** and sign in with GitHub.
2. **+ New → Web Service** → choose the `caliphate-backend` repository (click *Configure GitHub* to give
   Render access if it isn't listed).
3. Fill in:

   | Setting | Value |
   |---|---|
   | Name | `caliphate-api` (this becomes `https://caliphate-api.onrender.com`, or similar if taken) |
   | Language | **Node** |
   | Branch | `main` |
   | Region | **Frankfurt (EU Central)** |
   | Root Directory | leave empty |
   | Build Command | `npm install --omit=dev` |
   | Start Command | `node src/server.js` |
   | Instance Type | **Free** |

4. **Environment Variables**: add each of these (*Add Environment Variable*):

   | Key | Value |
   |---|---|
   | `NODE_ENV` | `production` |
   | `NODE_VERSION` | `22` |
   | `JWT_SECRET` | click **Generate** (or paste 40+ random letters and numbers) |
   | `MONGODB_URI` | your string from Part 1, step 5 |
   | `ADMIN_EMAIL` | the email you'll sign in to the dashboard with |
   | `ADMIN_PASSWORD` | a password of 10+ characters for the dashboard |
   | `SMS_PROVIDER` | `console` |
   | `ALLOW_CONSOLE_SMS` | `true` |
   | `STORAGE` | `mongo` |

5. Open **Advanced** → **Health Check Path** → `/health`.
6. Click **Deploy Web Service**.

The first build takes 2–4 minutes. Watch the **Logs** tab. When it's working you'll see these messages
(each log line is a bit of JSON; the message is after `"msg":`):

```
connected to MongoDB
Fares: set to ₦500 per km, ₦500 minimum, 15% commission.
Places: added 30 Sokoto places.
Admin: created you@example.com (owner).
Caliphate Rides API running
```

The server sets up the database by itself on its first start. There's nothing to run by hand.

---

## Part 4. Check it

Use your own address from the top of the Render page (e.g. `https://caliphate-api.onrender.com`):

1. **`https://caliphate-api.onrender.com/health`** shows `{"ok":true,"db":"connected"}`.
2. **`https://caliphate-api.onrender.com/dashboard`** shows the admin sign-in. Sign in with
   `ADMIN_EMAIL` / `ADMIN_PASSWORD`. You should see the Overview, and Fares at ₦500 per km.
3. Once you can sign in, you can delete `ADMIN_PASSWORD` from Render's Environment (it's only used to
   create the first admin). Add more admins from the dashboard's **Admins** page.

---

## Part 5. Point the app at it

In the app folder (`caliphate-rides`), in `.env`:

```
EXPO_PUBLIC_USE_MOCK=false
EXPO_PUBLIC_API_URL=https://caliphate-api.onrender.com
```

and for app builds, add the same two to `eas.json` → `build` → `base` → `env`.
Restart Expo (`npx expo start -c`) so it picks them up.

**Signing in from the app while SMS is off:** enter your phone number, then in Render → **Logs**
type `code is` in the search box. You'll find a line like

```
{"level":"info","msg":"SMS (not sent: SMS_PROVIDER=console)","to":"+2348031234567","message":"Your Caliphate Rides code is 482913. It expires in 5 minutes. ..."}
```

Type that code (here `482913`) in the app within 5 minutes. Every sign-in code appears there until SMS
is set up.

## Things to know

- **The free plan sleeps** after 15 minutes with no requests. The next request wakes it, which takes
  about a minute, so the app may say it can't connect the first time. Open `/health` in a browser to
  wake it, then try again.
- **Every push to GitHub redeploys** automatically. Changing an environment variable restarts it.
- **Atlas free storage is 512 MB.** Plenty for testing. Driver document photos use most of it.
- **Map routes** use the public OSRM demo server until you deploy your own routing server; then set
  `ROUTING_URL` to it.

## If it doesn't start

Open **Logs** and look for `failed to start`. The line includes a `hint`:

| You see | Fix |
|---|---|
| `bad auth` / `authentication failed` | Wrong username or password in `MONGODB_URI`. Re-copy it, and check `<db_password>` was replaced. |
| `ENOTFOUND` / `querySrv` | The address part of `MONGODB_URI` is wrong. Copy it again from Atlas → Connect → Drivers. |
| `Server selection timed out` | Atlas → Network Access must include `0.0.0.0/0`. |
| `Settings need attention: JWT_SECRET…` | Add `JWT_SECRET` (40+ characters). |
| `Settings need attention: SMS_PROVIDER…` | Add `ALLOW_CONSOLE_SMS` = `true`. |
| Build fails with `npm ERR!` | Check `package.json` is at the top of the repository, not inside a folder. |

## Later: real SMS and payments

Add these under Render → **Environment** when you have the accounts (see README sections 4 and 5):

- **Termii**: `SMS_PROVIDER=termii`, `TERMII_API_KEY`, `TERMII_BASE_URL`, `TERMII_SENDER_ID`, then
  delete `ALLOW_CONSOLE_SMS`.
- **Flutterwave**: `FLW_SECRET_KEY`, `FLW_WEBHOOK_HASH`; webhook URL
  `https://caliphate-api.onrender.com/payments/flutterwave/webhook`. For driver withdrawals, whitelist
  Render's outbound IPs (your service → **Connect** → **Outbound**) in Flutterwave.
